# Phase 5: Authentication

Forge provides a first-class, type-safe authentication system using **Bearer tokens** (API tokens) and `axum-login` for credential verification. Identity is established via `Authorization: Bearer <token>`; scope (organization and role) is provided by request headers (`X-Organization-Id`, `X-Role-Name`).

## Objectives

1.  **Integrated Identity**: Out-of-the-box support for user authentication and token-based identity.
2.  **Explicit Schema**: Migrations for the `user` table and `api_tokens` (token hashes for lookup).
3.  **Security by Default**: Secure password hashing using Argon2id; API tokens stored as hashes; no server-side sessions.
4.  **Cohesive DX**: User model implements `axum_login::AuthUser`; first-class routes for login, registration, token creation, and profile (scope) from headers.

## Architecture

### 1. Database Schema

Migrations generated by `forge new` include:

*   **`m..._create_user_table.rs`**:
  *   `id`: UUID (Primary Key)
  *   `email`: String (Unique, Not Null)
  *   `password_hash`: String (Not Null)
  *   `is_active`: Boolean (Default: true)
  *   `is_admin`: Boolean (Default: false)
  *   `created_at`: DateTime
  *   `updated_at`: DateTime

*   **`m..._create_api_tokens_table.rs`** (or equivalent): stores token hashes for Bearer lookup; no sessions table.

### 2. Forge Library (`crates/forge`)

*   **`forge_auth::token_auth`** (crate `forge-auth`):
  *   `hash_password(password: &str) -> Result<String, Error>`
  *   `verify_password(password: &str, hash: &str) -> Result<bool, Error>`
  *   Uses `argon2` with default recommended settings.
*   **`forge::app`**:
  *   `App::with_auth<B>()` registration method.
  *   Orchestrates the middleware stack (Tracing, TokenAuthLayer, etc.).

### 3. Database Crate (`crates/db`)

*   **`auth.rs`**:
  *   `AuthBackend` struct implementation of `axum_login::AuthnBackend`.
  *   Encapsulates SeaORM logic for fetching users during authentication.

### 4. Application Crate (`crates/app`)

*   **Generated Routes** (all under `/api/auth`; JSON API, no pages):
  *   `POST /api/auth/register`
  *   `POST /api/auth/login`
  *   `GET /api/auth/logout`
  *   `POST /api/auth/forgot-password` (placeholder logic)
  *   `POST /api/auth/reset-password` (placeholder logic)
  *   `GET /api/auth/profile` (requires authentication)

## Success Criteria

*   **E2E Verification**: A test case where a user registers or logs in, receives a token in the response, and successfully accesses protected endpoints with `Authorization: Bearer <token>` and scope headers.
*   **Performance**: In-process E2E auth tests complete in sub-0.05s.
*   **Safety**: Passwords are never stored in plain text; tokens are stored as hashes; no server-side session store.
