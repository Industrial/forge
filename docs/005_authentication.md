# Phase 5: Authentication & Session Management

Forge provides a first-class, type-safe authentication and session management system powered by `tower-sessions` and `axum-login`.

## Objectives

1.  **Integrated Identity**: Out-of-the-box support for user authentication and session persistence.
2.  **Explicit Schema**: Verbose migrations for both the `user` table and the `sessions` metadata.
3.  **Security by Default**: Secure password hashing using Argon2id and session-based authentication.
4.  **Cohesive DX**: A `#[derive(ForgeAuthUser)]` macro and first-class routes for login, registration, and profile management.

## Architecture

### 1. Database Schema

Two explicit migrations are generated by `forge new`:

*   **`m..._create_user_table.rs`**:
  *   `id`: UUID (Primary Key)
  *   `email`: String (Unique, Not Null)
  *   `password_hash`: String (Not Null)
  *   `is_active`: Boolean (Default: true)
  *   `is_admin`: Boolean (Default: false)
  *   `created_at`: DateTime
  *   `updated_at`: DateTime

*   **`m..._create_sessions_table.rs`**:
  *   Standard `tower-sessions` SQLx store schema for SQLite.

### 2. Forge Library (`crates/forge`)

*   **`forge::auth`**:
  *   `hash_password(password: &str) -> Result<String, Error>`
  *   `verify_password(password: &str, hash: &str) -> Result<bool, Error>`
  *   Uses `argon2` with default recommended settings.
*   **`forge::app`**:
  *   `App::with_auth<B>()` registration method.
  *   Orchestrates the middleware stack:
      1.  `Tracing`
      2.  `SessionLayer` (via `tower-sessions`)
      3.  `AuthManagerLayer` (via `axum-login`)
*   **`forge-macros`**:
  *   `#[derive(ForgeAuthUser)]` to automatically implement the required `axum_login::AuthUser` trait for the `User` model.

### 3. Database Crate (`crates/db`)

*   **`auth.rs`**:
  *   `AuthBackend` struct implementation of `axum_login::AuthnBackend`.
  *   Encapsulates SeaORM logic for fetching users during authentication.

### 4. Application Crate (`crates/app`)

*   **Generated Routes**:
  *   `POST /auth/register`
  *   `POST /auth/login`
  *   `POST /auth/logout`
  *   `POST /auth/forgot-password` (placeholder logic)
  *   `POST /auth/reset-password` (placeholder logic)
  *   `GET /auth/profile` (requires authentication)

## Success Criteria

*   **E2E Verification**: A test case where a user registers, logs in, receives a session cookie, and successfully accesses their profile.
*   **Performance**: In-process E2E auth tests complete in sub-0.05s.
*   **Safety**: Passwords are never stored in plain text; sessions persist correctly in the database.
