# 002_config: Phase 2 Configuration System

## Overview

The `002_config` integration test validates that the Forge CLI can generate and serve projects with configuration-driven behavior. This represents **Phase 2** of the Forge framework: "Config and conventional layout" using Figment.

## Goals

- CLI can generate configured Forge projects with `forge new`
- Configuration is the **single source of truth** (no CLI flags for settings)
- App builder automatically loads config without explicit user code
- Strict requirement: no config = crash (fail fast)
- Minimal, extensible config structure

## Architecture Decisions

### 1. Configuration is the Single Source of Truth

**Decision**: No CLI flags for configuration values (port, host, etc.).

**Implication**: 001's `--port` flag is removed in 002. All server settings come from `config/app.toml`.

**Rationale**:
- Aligns with "one config story" principle from the plan
- Simplifies mental model: one place to configure
- Enables environment-specific overrides via Figment's layered providers

**User Experience**:
```bash
# Change port - edit config/app.toml
$ cat config/app.toml
[server]
port = 3001

$ forge serve  # Uses port 3001 from config
```

### 2. Automatic Config Loading in App::new()

**Decision**: `App::new()` constructor automatically loads `config/app.toml` using Figment.

**Implementation**:
```rust
// src/main.rs in generated project
use forge::App;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    App::new()  // Automatically loads config/app.toml via Figment
        .route("/", || async { "Hello from Forge!" })
        .serve()
        .await
}
```

**Rationale**:
- Zero boilerplate for users
- Opinionated: config loading is not optional
- Side effect on construction is acceptable for framework code

**Error Handling**:
- If `config/app.toml` is missing: Figment returns error, process crashes
- No explicit pre-flight check - let Figment's error propagate
- Error message will be: `configuration file "config/app.toml" does not exist`

### 3. Config File Structure: app.toml Only (002)

**Decision**: `forge new` generates only `config/app.toml`. `config/db.toml` added in Phase 3.

**Generated app.toml**:
```toml
# Forge Configuration File
# See: https://forge.rs/docs/config

[app]
name = "myapp"
environment = "development"  # development | production | test

[server]
host = "127.0.0.1"
port = 3000
```

**Rationale**:
- Minimal but not cryptic - includes teaching comments
- Extensible sections can be added in later phases
- Follows TOML convention with clear section headers

### 4. The ForgeConfig Struct

**Design**:
```rust
use serde::Deserialize;

#[derive(Debug, Clone, Deserialize)]
pub struct ForgeConfig {
    pub app: AppConfig,
    pub server: ServerConfig,
}

#[derive(Debug, Clone, Deserialize)]
pub struct AppConfig {
    pub name: String,
    pub environment: String,
}

#[derive(Debug, Clone, Deserialize)]
pub struct ServerConfig {
    pub host: String,
    pub port: u16,
}
```

**Rationale**:
- Flat TOML maps to nested structs (Figment handles this)
- Extensible: add `database: DatabaseConfig` in Phase 3
- Derives Clone so config can be shared across tasks/handlers

### 5. Project Structure Generated by `forge new`

**Phase 2 Scope** (config files only):
```
myapp/
├── Cargo.toml          # Dependencies: forge, tokio
├── config/
│   └── app.toml        # App and server configuration
└── src/
    └── main.rs         # Uses App::new() with auto-config loading
```

**Not in Phase 2**:
- No `config/db.toml` (Phase 3)
- No `database/migrations/` (Phase 3)
- No `src/routes.rs` (convention, not required)
- No `.env` file (use TOML config only)

**Library Exports** (`src/lib.rs`):

### Phase 2B: CLI Enhancement (`crates/forge-cli/`)

**Remove from 001**:
- `--port` CLI flag (no longer supported)
- Update help text to reflect config-driven behavior

**Add `new` subcommand**:
```rust
#[derive(Parser)]
#[command(name = "forge")]
enum Commands {
    /// Create a new Forge project with configuration
    New {
        /// Project name
        name: String,
    },
    /// Serve the current directory's Forge project
    Serve,
    /// Version information
    #[command(name = "--version")]
    Version,
}
```

**`new` command flow**:
1. Create project directory: `./{name}/`
2. Generate `Cargo.toml` with forge dependency
3. Generate `config/app.toml` with project name and defaults
4. Generate `src/main.rs` with minimal forge::App usage

**`serve` command updates**:
- Keep 001's project detection (Cargo.toml, forge dependency, src/main.rs)
- Remove explicit port handling
- Spawn `cargo run` which will crash if config missing (expected behavior)

#[tokio::test]
async fn test_forge_new_generates_app_toml() {
    // Arrange: temp directory
    let temp_dir = TempDir::new().unwrap();
    
    // Act: run `forge new test_app`
    let mut cmd = Command::new("forge");
    cmd.arg("new")
        .arg("test_app")
        .current_dir(&temp_dir);
    
    // Assert: success exit code
    cmd.assert().success();
    
    // Assert: config/app.toml exists
    let config_path = temp_dir.path().join("test_app/config/app.toml");
    assert!(config_path.exists());
    
    // Assert: content contains expected values
    let content = fs::read_to_string(&config_path).unwrap();
    assert!(content.contains(r#"name = "test_app""#));
    assert!(content.contains(r#"port = 3000"#));
    assert!(content.contains(r#"[app]"#));
    assert!(content.contains(r#"[server]"#));
}

#[tokio::test]
async fn test_forge_serve_uses_config_port() {
    // Arrange: create project with custom port
    let temp_dir = TempDir::new().unwrap();
    create_project_with_port(&temp_dir, "test_app", 3333).await;
    
    // Act: start server
    let mut child = Command::new("forge")
        .arg("serve")
        .current_dir(temp_dir.path().join("test_app"))
        .spawn()
        .unwrap();
    
    // Wait for server startup
    tokio::time::sleep(Duration::from_secs(2)).await;
    
    // Assert: server responds on configured port
    let response = reqwest::get("http://127.0.0.1:3333/").await.unwrap();
    assert!(response.status().is_success());
    
    // Cleanup
    child.kill().await.unwrap();
}

#[tokio::test]
async fn test_forge_serve_crash_without_config() {
    // Arrange: create minimal project without config
    let temp_dir = TempDir::new().unwrap();
    create_minimal_project_no_config(&temp_dir, "test_app").await;
    
    // Act: run `forge serve`
    let output = Command::new("forge")
        .arg("serve")
        .current_dir(temp_dir.path().join("test_app"))
        .output()
        .await
        .unwrap();
    
    // Assert: process fails
    assert!(!output.status.success());
    
    // Assert: error mentions config/app.toml
    let stderr = String::from_utf8_lossy(&output.stderr);
    assert!(stderr.contains("config/app.toml") || stderr.contains("configuration file"));
}

#[tokio::test]
async fn test_no_port_flag_in_cli() {
    // Arrange: valid project
    let temp_dir = TempDir::new().unwrap();
    create_project(&temp_dir, "test_app").await;
    
    // Act: try to use --port flag (should fail)
    let output = Command::new("forge")
        .args(["serve", "--port", "4000"])
        .current_dir(temp_dir.path().join("test_app"))
        .output()
        .await
        .unwrap();
    
    // Assert: CLI rejects unknown flag
    assert!(!output.status.success());
    let stderr = String::from_utf8_lossy(&output.stderr);
    assert!(stderr.contains("error: unexpected argument '--port'"));
}

## Dependencies & Ecosystem

### Configuration Stack
- **figment**: Multi-source configuration (file + env overlay)
- **serde**: Derive macros for config structs
- **toml**: TOML format support (via figment features)

### Retained from 001
- **axum**: Web framework (unchanged)
- **tokio**: Async runtime (unchanged)
- **clap**: CLI argument parsing (remove port flag)

## Safety & Error Handling

### Config Loading Errors
- **Missing file**: Figment returns error with file path
- **Parse errors**: Figment provides line numbers and context
- **Missing fields**: Serde provides field names

### No Graceful Degradation
- Config is required - no "default mode"
- Crash early with clear error message
- Forces users to create proper project structure

### Type Safety
- Config values validated at load time via Serde
- Invalid port (e.g., "abc") caught before server starts
- Invalid environment strings caught early

## Testing Strategy

### E2E Tests (Primary)
- Full CLI workflow: `forge new` → `forge serve`
- HTTP validation with `reqwest`
- Process lifecycle management
- Error message verification

### Integration Tests (Secondary)
- Config struct serialization/deserialization
- Figment provider composition
- Default value handling

### Unit Tests (Minimal)
- Config struct validation
- Error type conversions

## Success Criteria

**Functional**:
- `forge new myapp` creates project with `config/app.toml`
- Generated config contains correct project name
- Generated config contains sensible defaults (port 3000, localhost)
- `forge serve` reads config and starts server on configured port
- Missing config causes process exit with error
- `--port` flag is rejected (not supported)

**User Experience**:
- Clear config format with teaching comments
- Generated main.rs shows minimal usage
- Error messages identify missing config file
- Fast startup time (< 2 seconds with config)

**Code Quality**:
- Config loading is automatic and invisible
- Extensible structure for future phases
- Comprehensive E2E test coverage
- No CLI flag pollution

## Summary

002_config establishes the "one config story" for Forge:

| Principle | 001 (Phase 1) | 002 (Phase 2) |
|-----------|---------------|---------------|
| **Port setting** | `--port` CLI flag | `config/app.toml` |
| **Config loading** | N/A (hardcoded) | Automatic in `App::new()` |
| **Config required** | No | Yes (crash if missing) |
| **Config files** | None | `config/app.toml` |
| **Generate config** | N/A | `forge new` creates it |

This phase delivers the foundation for all subsequent configuration needs while maintaining strict convention and minimal boilerplate.
