### Missing in Core HTTP & routing (item 6): typed route helpers / reverse routing

**What it is:** Generating URLs from a *route name* (and optional path/query params) instead of hardcoding strings like `"/api/auth/profile"` or `"/users/".to_string() + &id.to_string()`. Used for redirects, links in JSON, emails, and templates so paths stay correct when routes change.

**Should it live in an existing feature?** Yes. It belongs in the same place routes are defined — the **App** and its `route` / `post_route` API (numbers 1–5). Forge already has the router and handler registration; reverse routing is the missing “other side”: a way to go from *name (and params)* → *path or full URL*.

**How to implement:**

1. **Named routes on `App` (runtime registry)**  
   - Add optional naming to registration, e.g. `app.route("/", handler).name("home")` or `app.named_route("profile", "/api/auth/profile", get(handler))`.  
   - Store a map in `App`: `HashMap<String, PathTemplate>` (or `(Method, PathTemplate)` if you need method for debugging). `PathTemplate` is the path string with placeholders, e.g. `"/users/:id"`.  
   - Expose a helper used in handlers (or in state): e.g. `forge::reverse("profile")` → `"/api/auth/profile"`, `forge::reverse("user_show", [("id", id)])` → `"/users/123"`.  
   - Optionally take base URL from `config.server` so you can generate full URLs for emails/redirects.  
   - **Pros:** Matches Rails/Django/AdonisJS style; one registry. **Cons:** Stringly-typed names; typos only caught at runtime.

2. **Typed route enum (compile-time, no registry)**  
   - Define an enum in the app (or generated by macro) with one variant per route, e.g. `Route::Home`, `Route::AuthProfile`, `Route::UserShow { id: Uuid }`.  
   - Implement `.path()` (and optionally `.url(base: &str)`) on the enum. Paths live next to the enum; the router still gets the same path strings when building the app.  
   - **Pros:** Refactor-safe, no string names, single source of truth. **Cons:** Paths are duplicated (enum + `app.route(...)` unless you drive routing from the enum or a macro).

3. **Hybrid**  
   - Keep `route("/path", handler)` as today. Add a separate, optional `RouteNames` type (enum or struct with constants) that the app defines and uses for `redirect(RouteNames::AuthProfile)` and link generation. The framework only needs a small helper to build path strings from a spec (e.g. `path_spec("/users/:id", [("id", id)])`) so the enum stays thin.

**Recommendation:** Start with (1) if you want framework-level support and consistency with other frameworks: add `name()` or `named_route` to `App`, store path templates, and provide `forge::reverse(name, params)` (and optionally `reverse_url` using server config). If you prefer maximum type safety and fewer framework changes, (2) or (3) can be done entirely in app code with a tiny helper in Forge for path interpolation.

# What Forge is missing (summary)

Compared to AdonisJS, Rails, and Django, Forge currently **does not** include:

### Critical / high impact

1. **CSRF protection** — no built-in CSRF tokens or middleware.
2. **File uploads** — no multipart handling, validation, or storage (local/cloud).
3. **Email** — no mail sending, templates, or async delivery.
4. **Background job queue** — only in-process cron; no queue (e.g. Redis), retries, or job UI.
5. **Static file serving** — no built-in static/assets pipeline or serving.
6. **Server-side templates** — no template engine, layouts, or form helpers (API-only by default).
7. **OpenAPI / API docs** — no generated spec or Swagger UI.
8. **Admin UI** — no auto-generated CRUD admin like Django’s.

### Important

9. **Secrets / credentials** — no dedicated secrets manager; env only.
10. **Type-safe env** — config is TOML; env vars not validated/typed by framework.
11. **Multiple DB connections** — single DB only.
12. **API tokens** — session-based auth only; no bearer/API key auth.
13. **OAuth / social login** — not built-in.
14. **Password reset** — no built-in flow.
15. **WebSockets / real-time** — no Action Cable / Channels equivalent.
16. **CORS** — no built-in CORS layer (must add manually).
17. **Pagination helpers** — no standard pagination type or helpers.
18. **CLI beyond new/serve** — no `forge run`, migrations command, or REPL.
19. **Caching** — no cache abstraction (memory/Redis).
20. **i18n** — no translations or locale formatting.

### Nice to have

21. **Clickjacking / CSP** — no X-Frame-Options or CSP helpers.
22. **Route name / reverse routing** — no typed URL generation from route names.
23. **Metrics endpoint** — no Prometheus/OpenMetrics.
24. **REPL / console** — no `forge console` or equivalent.
25. **Database console** — no `forge db` shell.
